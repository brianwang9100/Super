# Optional OpenAI narration

Optional, explicitly configured OpenAI narration alongside built-in Apple voices.

## User setup

Settings → Narration presents two connection cards in the model-list style: **Apple enhanced voices** and **OpenAI**. Each card shows a blue **Set up** action until configured, then muted **Configured** text; tapping the card opens its setup or management modal. Apple's status comes from installed Enhanced/Premium voices and is refreshed when returning from Settings. Its modal explains the Read & Speak (or Spoken Content) → Voices download steps and links into iOS Settings. OpenAI's modal accepts a narration-only API key and explains billing and data sharing. A top-right checkmark Save action, matching the note editor’s glass and haptic treatment, connects the chosen key, enables OpenAI narration, and returns to the connection list; there is no enable toggle in this modal. Save stays disabled until a new or existing credential is selected. Reopening a saved narration-only key shows synthetic bullets, just like model registration; focusing clears the placeholder for replacement, and leaving it untouched preserves the Keychain entry. The form never reads the saved secret into its field. The saved-key caption and preview, stop-preview, and remove-key buttons are omitted. A red **Clear downloaded narration** action opens a native confirmation explaining that playback stops, downloaded audio is removed, and regenerating it may incur API charges; Cancel leaves the downloads intact. A saved but disabled OpenAI connection remains configured, with a subtitle stating that narration is turned off. Settings → Models → OpenAI also offers **Use OpenAI voices for narration**, defaulting on in a new setup draft. Saving the draft confirms that choice; canceling does nothing. Existing installs remain unconfigured until the user saves. An explicitly saved off preference remains off when another model is added.

The user selects one narration credential. Adding another Chat model preserves that selection unless **Use this key for narration** is chosen. The active Chat model has no effect on the narration provider. Only credentials explicitly identified as OpenAI and using its canonical HTTPS endpoint qualify; protocol-compatible custom servers are not OpenAI credentials. Legacy model rows gain an explicit provider identity when their setup is saved.

The voice chooser uses a native popover up to 360 points wide, with fixed OpenAI-then-Apple sections and accessible company labels. Marin is the first OpenAI default, followed by Cedar and the remaining built-in voices. The selected control shows the voice name and company on separate lines; menu rows also include the company. Apple remains available without a key. OpenAI failures offer Retry or **Use Apple voice**, without silently switching billing sources. Retry resumes the failed verse within the original selection using the current voice, including failures before buffering or playback starts; normal Play after Stop restarts the selection. Changing speed during temporary Apple recovery preserves the saved OpenAI voice for the next session.

While audio is preparing, the shared play/pause button displays an activity indicator without changing the player's height. It remains tappable to pause and exposes “Preparing audio” as its accessibility value. The same control handles initial preparation for Apple and OpenAI; downloaded verses hand off without entering a loading state. A slow look-ahead request reports buffering before waiting for the download, and playback clears that state when the next clip starts.

Saving never requests speech. Play in the narration player starts generation. The setup modal explains AI-generated audio and API billing; the player keeps its company label without repeating that disclosure. A ChatGPT subscription does not include API usage.

## Implementation

- Core owns `SpeechGenerating`, the fixed OpenAI speech request, `ProviderAudioSetup` (a company-neutral composition contribution), and main-actor `AudioActivity` for microphone arbitration.
- Bible owns the narration settings record and GRDB repository, Keychain-backed setup controller, provider-neutral voice identity, cloud playback service, native audio player, and audio cache.
- Chat persists optional `providerId` metadata and commits the audio setup contribution only after model/key saving succeeds. Credential changes are published through the event bus. Fresh Chat key references are tracked in its existing database before Keychain writes; rotation atomically publishes the replacement and tracks the retired reference. Failed cleanup remains discoverable at the next launch, before providers and model editing become available.
- SuperBible's composition root connects Chat's safe credential references to Bible's setup; neither applet imports the other. SuperOS continues to use Apple narration.
- The speech request uses `gpt-4o-mini-tts-2025-12-15`, MP3, generation speed 1, and calm verbatim-reading instructions. Playback speed is applied locally. HTTPS redirects are refused.
- Authentication failures are classified from the provider's structured reason: only an explicit `invalid_api_key` becomes an invalid-key message. Missing scopes or insufficient permissions explain audio/project access; an unrecognized 401 remains a general authorization failure. Logs contain only the HTTP status and a closed set of local failure names, never provider messages, response bodies, or credentials.
- Verse text is split at word boundaries under a conservative 1,600 UTF-8-byte limit, preserving the input text. Highlighting follows audible playback events. Only one following verse's first clip is prefetched, starting after the current clip reports audible playback.
- Stop, navigation, provider changes, and microphone capture invalidate pending playback generations. Late responses cannot start playback. Pause while downloading waits before starting the player.
- System audio interruptions cancel narration while retaining valid downloaded clips. Native resume refusal ends the session with an audio-session recovery error and retains the clip. Audio-session availability failures are separate from decoding failures, which evict only the invalid clip. Apple fallback resumes from the latest audible verse even when it came from cache.
- Preferences live in Bible's single `narrationSettings` row with revision checks. Raw keys live only in Keychain, using the same `AppleKeychainClient` as model registration and `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`. Narration-only keys are owned by Narration settings and retired when replaced; borrowed Chat keys are never deleted by narration cleanup. A staged-reference ledger in the same Bible database records fresh references before Keychain writes, without changing the active narration revision. A successful settings commit removes its staged entry atomically; failed rollback remains discoverable for cleanup on reload.
- Generated audio lives in a backup-excluded, disposable file cache under Caches, bounded to 100 MiB of audio with least-recently-used eviction. The key includes exact text, model, instructions, format, and voice. Clips are written atomically, with metadata rebuilt from owned clip files when the cache opens; no second SQLite database or migration is involved. If disk cache initialization fails, playback uses an in-memory cache that retains a disk-cleanup retry. Clear retries the original disk location and reports failure if persistent clips cannot be removed before clearing memory. Startup and explicit clearing remove abandoned temporary clips owned by this cache. The new clips directory leaves earlier, unshipped experimental cache files untouched.
- Look-ahead retains its downloaded bytes independently of cache persistence, so full/unavailable caches and oversized clips do not cause a second generation request. Directory lookup and disk-cache opening both fall back to memory on failure. Next joins an already submitted look-ahead request when its text and voice match the destination, avoiding duplicate generation. Stop, a different destination, and voice changes still cancel obsolete requests.
- Editing a Chat key stages the replacement under a fresh Keychain reference, then publishes that reference through the committed model row. A failed save leaves the previous row and key untouched. Narration follows its explicitly selected model ID to the current committed key, rechecking after asynchronous reads; provisional replacements cannot be used for speech. Updates compare the previously read credential reference atomically, so a stale edit cannot restore a retired key or resurrect a deleted model. Unreferenced old keys are cleaned up after a successful save, including reference checks for model kinds written by newer app versions.
- Enabling OpenAI selects Marin when no voice preference exists, including after a prior opt-out; explicit Apple or OpenAI preferences are preserved.
- Metadata-only Chat model edits and unchanged audio-setup commits preserve narration playback and pending credential reads. Changes to the credential reference or direct-OpenAI eligibility invalidate it. Deleting a model also unregisters its live provider if the repository reports a partial deletion failure, preventing further requests through its retained credential.
- Playback remains foreground-only, enforced by an app-lifetime scene observer even when the Bible backdrop is hidden. No microphone recording or live voice conversation is added by this feature.

### Queue design

Keep the provider-neutral verse queue: Apple synthesizes queued utterances locally, while OpenAI generates and caches verse clips with one-verse look-ahead. This preserves verse highlighting, skip/restart controls, selected passages, and bounded speculative API usage. Whole-chapter audio would need a separate way to map playback positions to verses and seek within the recording. If listening tests still reveal gaps on short verses, evaluate a bounded buffer of upcoming clips while retaining the same queue and transport interface.

## Validation

Automated checks cover request fields, safe errors, input limits, company identity, opt-in and opt-out persistence, key ownership, explicit credential selection, stale drafts, cache eviction, Unicode segmentation, late-response cancellation, pause during buffering, microphone preemption, and Chat's two-step setup commit. Schema snapshots include the additive settings, provider metadata, and staged-reference migrations. The connection list, Apple download modal, OpenAI setup modal, and narration player have light, dark, and XXL snapshots. Automated validation includes the Core, Chat, and Bible package suites plus iOS snapshots of connections, setup, the voice chooser, and transport layouts; the PR records exact commands and current results. The authentication regression first reproduced permission-related and unrecognized 401 responses being mislabeled as invalid keys; it passes with reason-based classification. The Keychain rejection regression asserts that a failed secure write leaves no enabled connection or credential reference. Transport snapshots intentionally remove the repeated billing footer, put buffering inside the center button, and cover permission and general authorization errors. Buffering tests cover cached handoffs, waiting on unfinished look-ahead, pausing that wait, and returning to audible playback within a segmented verse. Cache-clearing coverage verifies that playback stops and downloaded audio is deleted while the narration credential and enabled connection remain intact. The native ProgressView has no app-specific Reduce Motion branch; the snapshot harness cannot override SwiftUI’s read-only Reduce Motion environment. An injected installed-voice probe verifies that Apple’s connection status updates after a download; the narration picker rescans when returning to the app or closing connection settings.

Use a dedicated worktree simulator with the CI environment in [TESTING.md](../TESTING.md). Build the interactive app with `CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`: unsigned simulator builds cannot save Keychain entries. User testing confirmed OpenAI voice selection and playback. Check the remaining listening and device-specific behavior with these steps:

1. Open Apple’s **Set up** modal, check the download instructions and Settings link, then return. On a device with downloaded Enhanced/Premium voices, confirm **Configured** and the updated narration voice menu.
2. Open OpenAI’s **Set up** modal and save the narration-only key. Confirm its card changes to **Configured**, then play Marin from the narration player and listen for pronunciation, naturalness, clipping, and startup latency.
3. Open a chapter's Narrate action. Confirm OpenAI is above Apple and both the menu and selected control clearly identify the company.
4. Try pause/resume, 0.75×–2× speeds, next/previous verse, and switching company while speaking.
5. Stop during preparation, navigate to another chapter, and background the app. Audio must not restart afterward.
6. Choose Apple in the voice picker and confirm Apple remains usable without OpenAI requests. Open OpenAI settings and tap **Clear downloaded narration**. Cancel once to verify downloads remain; confirm on a disposable cache to verify playback stops and downloads are cleared while the connection remains configured.
7. Try an invalid key / airplane mode and verify the recovery message and explicit Apple fallback. Replay cached audio offline.
8. Add an OpenAI Chat model, then a second one. Confirm the draft toggle defaults correctly and the original narration key remains selected unless explicitly replaced.

Disk-cache tests cover reopening, LRU eviction, atomic replacement, owned-file filtering, and injected read/write/removal failures. The iOS simulator verifies replacement bytes but does not expose file protection attributes; the protection assertion runs on physical iOS devices. Automated tests use in-memory credentials and mocked speech requests. Production billing, subjective audio quality, Bluetooth routes, and physical-device interruptions remain manual checks. When a borrowed Chat credential is deleted, the setup form returns to manual key entry so a replacement can be supplied. New model drafts also treat that unavailable source as absent and select the new key for narration by default, while preserving any saved opt-out.

API reference: [OpenAI text-to-speech guide](https://developers.openai.com/api/docs/guides/text-to-speech).

Apple setup instructions follow the [iOS Read & Speak guide](https://support.apple.com/guide/iphone/hear-whats-on-the-screen-or-typed-iph96b214f0/ios) and [enhanced voice download guidance](https://support.apple.com/en-us/111798). Deep linking is best-effort; the modal also gives the full navigation path if iOS opens Settings at another location. The dedicated iOS simulator opens the Settings home screen and exposes a reduced Spoken Content pane without voice downloads, so installing Enhanced/Premium voices requires physical-device validation.
